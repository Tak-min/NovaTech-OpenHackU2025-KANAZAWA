# SoraLog UI Redesign Design Notes

作成日: 2026-05-22

## 1. 現状UIの観察メモ

調査対象:

- 公開フロントエンド: `https://soralog-qnka.onrender.com/`
- スマートフォン表示: 幅390px前後
- PC表示: 1366px幅
- 取得スクリーンショット:
  - `docs/screenshots/public-login-mobile.png`
  - `docs/screenshots/public-register-mobile.png`
  - `docs/screenshots/public-home-mobile.png`
  - `docs/screenshots/public-map-mobile.png`
  - `docs/screenshots/public-ranking-mobile.png`
  - `docs/screenshots/public-settings-mobile.png`
  - `docs/screenshots/public-home-desktop.png`

画面構成:

- ログイン/新規登録は単独フォーム。大きな見出し、丸い入力欄、黄色の主要ボタンで構成されている。
- ログイン後は雲形ヘッダー画像、空背景、白い大きなカード、下部ナビゲーションの構成。
- ホームは称号、理由、判定画像、乗り遅れ回数、天気スコアゲージを縦に並べている。
- マップはLeaflet地図をカード内に表示している。
- ランキングはタブとテーブル。スマホではヘッダー文字が縦に折れ、情報が読み取りにくい。
- 設定はプロフィール、自己紹介、通知、位置情報、メール設定が1画面内にあるが、横並びが強く、390px幅では窮屈。

色使い:

- 既存の印象は「青空背景 + 白い雲 + 黄色アクセント」。
- ログイン/登録画面は白背景中心で、ログイン後画面との温度差が大きい。
- 黄色ボタンはハッカソン作品らしい明るさがあるが、やや強く、かわいい日記アプリ感には少し硬い。

フォントサイズ:

- 見出しや称号は大きく印象に残る。
- ランキングや設定ではテキストが大きすぎる箇所があり、折り返しや横あふれにつながっている。
- 全体ボタンに `font-size: 10px` が当たっており、局所的な指定と競合しやすい。

余白:

- ログイン/登録画面は上部の余白が大きく、フォームが下に寄り気味。
- ログイン後画面はカード内余白が広く、かわいさはあるが、情報密度の調整が必要。
- PCでは横に広がりすぎ、スマホアプリ風のまとまりが崩れている。

ボタンの形:

- 主要ボタンは丸く、黄色で押しやすい印象。
- 立体的な影はやや古く見えるため、柔らかいグラデーションと薄い影へ寄せる。
- 設定画面のリセット/保存ボタンは標準ボタン感が残る。

ナビゲーション:

- 下部ナビは既存の特徴として残したい。
- 雲のフッター画像とアイコンの組み合わせはSoraLogらしい。
- PCではフッター雲が巨大化し、画面下を覆いすぎる。

入力フォーム:

- ログイン/登録の入力欄は大きくタップしやすい。
- ラベル、入力欄、ボタンのまとまりが古いHTMLフォーム感に見える。
- 性別選択はラジオボタンそのままで、カード風に改善したい。

既存UIで残すべき特徴:

- 青空背景、雲形ヘッダー、雲形フッター。
- 丸い入力欄と大きめのボタン。
- ホームで称号を大きく見せる構造。
- 下部4タブナビゲーション。
- 既存画像 `hare_f.png`, `hare_m.png`, `ame_f.png`, `ame_m.png`, `background-sky.png`, header/footer画像。

崩れている箇所:

- PC表示で `#app` が横に広がり、フッター雲も巨大化してスマホアプリ感が消える。
- ランキングのテーブルヘッダーが縦書きのように折れる。
- 設定画面の横並びが窮屈で、ユーザー名や入力欄がはみ出しやすい。
- スクロールバーが画面内で強く見え、アプリ感を損ねている。

スマホで使いにくい箇所:

- ログイン画面にアプリ名や使う楽しさの説明がなく、初見で何のアプリか分かりにくい。
- ホーム画面は称号以外の情報の優先度が整理されていない。
- マップ画面に位置情報公開の説明がない。
- ランキングは表形式のままで、順位や自分の行が楽しく見えにくい。
- 設定画面で「位置情報許可」が何に使われるかの説明が不足している。

PC表示で崩れている箇所:

- 画面全体がPC幅へ伸びる。
- フッター画像が横幅いっぱいに伸び、下部を大きく覆う。
- コンテンツカードとナビがスマホ幅でまとまらない。

## 2. デザインコンセプト

コンセプト:

```text
天気ログ × かわいい日記アプリ × やわらかいモダンUI
```

方向性:

- スマホで毎日開きたくなる、空と日記の雰囲気。
- 称号やランキングは、競争よりも「今日のわたしの天気ジンクス」を楽しむ見せ方。
- 白、淡い空色、薄いラベンダー、薄いピンクをベースに、コーラルピンクとミントを小さく差す。
- 既存の雲画像と黄色アクセントは残しつつ、色を少し柔らかくする。
- 位置情報や公開設定は、怖さを減らす説明文と状態表示を添える。

避ける方向性:

- 無機質な管理画面風UI。
- 原色の強いボタンだけに頼る見た目。
- 表やフォームがそのまま並んだ古いHTML感。
- PC前提の横長レイアウト。
- 情報を詰め込みすぎた画面。

## 4. 画面別の改善方針

### ログイン画面

- アプリ名 `SoraLog` と短い説明を追加する。
- フォームをカード化し、スマホ中央で読みやすくする。
- 入力欄を大きく、丸く、フォーカス状態を分かりやすくする。
- ログインボタンはコーラルからハニーへの柔らかいグラデーションにする。
- 新規登録導線はセカンダリボタンとして下に配置する。
- `alert()` は画面内トーストへ寄せる。

### 新規登録画面

- 初回利用のワクワク感が出る説明文を追加する。
- 入力項目をカード内にまとめる。
- 性別選択はラジオボタンを隠し、選択カード風にする。
- 入力ミス時はトーストで短く、やさしい文面にする。

### ホーム画面

- 称号を最も目立たせる。
- 理由、判定画像、乗り遅れ回数、天気スコアをそれぞれ小さな情報ブロックとして整理する。
- `晴れ男` / `雨女` などが楽しく見えるよう、称号の周囲に淡いアクセントをつける。
- スコアゲージは横幅可変にして、0地点と増減が分かりやすいようにする。

### マップ画面

- 地図をカード化し、スマホ幅で見切れないようにする。
- 地図の上に「公開中のユーザーだけ表示」などの説明を追加する。
- 位置情報公開に関する注意を、怖くない文面で表示する。
- ローディングや権限拒否時にも同じカード内で状態が分かるようにする。

### ランキング画面

- タブはセグメントコントロール風にする。
- テーブルはスマホではカード型ランキングに見えるようCSSで整える。
- 自分の順位は淡いブルー/ピンク背景で強調する。
- 読み込み中、エラー、空状態はカード中央に表示する。

### 設定画面

- プロフィール、自己紹介、通知、位置情報公開、アカウント設定にセクション分けする。
- アイコンアップロードは丸いプレビューと明確なボタンにする。
- トグルUIを柔らかいモダンな見た目にする。
- 保存ボタンの状態をトーストで表示する。
- 位置情報公開について「地図に表示されるのは許可した場合だけ」と説明する。

## 5. レスポンシブ方針

- スマートフォンを最優先にする。
- `#app` は `width: min(100%, 430px)` を基本にする。
- PCではスマホ幅のアプリが中央に置かれるようにする。
- PCで横に伸びすぎないよう、メディアクエリでも幅を広げない。
- 360px幅でもボタンやランキングが横あふれしないよう、グリッドと可変幅を使う。
- タップ領域は44px以上。
- 下部ナビゲーションは `env(safe-area-inset-bottom)` を考慮する。
- コンテンツ下部はナビに隠れないよう余白を確保する。

## 6. 実装方針

優先方針:

- 既存API仕様は変更しない。
- 既存の画面ID、フォームID、ボタンIDは維持する。
- `main.js` のイベント処理が参照している要素は削除しない。
- CSS変数でデザイントークンを定義する。
- 共通クラスを `app-shell`, `screen-card`, `field`, `primary-action`, `soft-card`, `section-title` などに整理する。
- 既存画像は継続利用する。
- `alert()` 依存を減らし、`showToast()` へ置き換えられる箇所から置換する。
- 本番では不要な `console.log` を抑制する。
- 位置情報や地図公開の説明をHTML上に追加する。
- PC表示はスマホアプリ風中央レイアウトに固定する。

今回の実装対象:

- `frontend/index.html`
- `frontend/src/style.css`
- `frontend/src/main.js`

将来的な分割案:

```text
frontend/src/
  api/client.js
  features/auth.js
  features/home.js
  features/map.js
  features/ranking.js
  features/settings.js
  features/locationTracking.js
```

今回はVanilla JS構成のまま、IDを守ってCSSと小さなJS補助関数で改善する。
